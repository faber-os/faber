## Things to keep in mind
- **Derived signals (D24)** are allowed, but they stay read-only and visibly separate from parts (`app:name` addresses, an "app" badge). SENNEP's `sennep:pose` is the test case. Watch that this doesn't grow into apps acting as connectors.
- **Signing keys (D27):** the Faber maintainer (Mikkel) holds the offline OS-image key and the registry-index key. Plan key rotation before the first signed release. No trust is based on GitHub accounts.
- **The first-chat idea "start with an install script" was replaced by D17** (develop on a PC, ship a real A/B image at the first public release).
- **The name:** only `Faber` / `faber` / `FABER` (CLAUDE.md rule 10). The GitHub org and npm scope are `faber-os`, because the bare names are taken.
- **Light is the default theme** (Mikkel, 2026-10-15), as D31 said. An explicit `theme = "system"` in settings.toml still follows the screen.
- **Shell/core mismatch:** a debug core used to read `shell/dist` from disk live, so an old running core served a new shell → 404s everywhere. Now `embed-shell` always embeds (`debug-embed`), and an API fingerprint makes any remaining mismatch (Vite dev + old core) show "Restart the Faber core".
- **Settings batch 1 notes:** wall-clock text is always `en-GB` (English UI, D44), so 12-hour shows "2:30 pm". Restore checks everything first, then applies config, then files; a failing file write midway leaves config restored (not all-or-nothing). Larger text scales text and rem spacing, not px chrome (taskbar, icons, window min sizes). Diagnostics strip paths and Bluetooth names, but USB serial numbers can still show in port ids. The time-zone list comes from the browser (some legacy names). Angles setting removed until something shows an angle.
- **Translations:** core error messages and hints stay English (only shell texts translate). Dates use fixed `en-GB` (open: follow the language?). "Copy diagnostics" stays English on purpose. Default names of new items ("New folder") are translated. Window titles are read at display time (`DesktopController.titleOf`), so open windows follow a language change; windows that name themselves (documents) keep their names.
- **Phase 2 decisions made by agents (review later):** maze corridors 1.1 m (SENNEP can't turn in 1.0 m); `empty` world has walls (an open floor gives the LiDAR nothing); table tops are overhead, so the machine drives under tables; `PortRequirement::Bridge` for generic parts; commands clamped by the core before parts see them; a base lease locks its motors via a `built-from` setting; manual distance values outside range report too-close/too-far with finite meters; `lease-ms` per-part setting not implemented yet (all 250 ms).
- **Phase 2 shell decisions (review later):** the big Stop in Drive engages the e-stop (same as the taskbar); the lease is taken on the first move and kept while Drive is in front; D46 "once per session" = until page reload; settings forms are in SI; generic connector defaults stay small (0.5 × 0.4 m, 0.5 m/s) and the form starts from a `suggested` SENNEP value instead; connector setting labels come from the core in English (not translatable yet); World has no desktop icon (Programs, pinnable).
- **Phase 3c (declarative connectors) decisions, review later:** manifests start with `faber-manifest = 1`; position fix names `fix2d`/`fix3d` (match the WIT); no fix → `fix: none` with lat/lon 0, no HDOP→accuracy; GGA quality 6–8 = no fix; example captures are generated by a test and committed (the GPS one is synthetic, Copenhagen City Hall Square); an installed connector can't take a built-in id. Not done: load problems only in the log (not API/shell), no `position@1` viewer, no USB hints for declarative manifests, no I²C/SPI register maps yet.
- **Downloads** stream from disk with no size cap (`download=1`); inline reads stay capped at 16 MB for Notes. Download names keep non-ASCII letters (`filename*`).
- **Settings proposal:** a separate session is researching what Settings should offer → `private/settings-proposal.md`.
- **Signal style's red accent** sits close to the danger red used for delete. Kept for now; move it to orange if it confuses.
- **Start menu shows all programs** (not its own pins): one pin system, the taskbar's (principle "one obvious way").
- **Disks:** a move between roots is refused (`bad-path`) until copy exists. Disk ids come from the drive letter on Windows (`disk-e`) and the mount label on Linux; two Linux sticks with the same label would collide (not handled yet).
- **Recent files** in the start menu live in the browser's storage, since the core keeps no list.
- **Processes:** never kill by name (`taskkill /IM node.exe` hit other programs). Run probe cores with `CARGO_TARGET_DIR=target/agent` on another port and stop them by PID.

## Phase 1 notes (2026-10-15)
- **Serial protocol was ambiguous** (found by the shell agent): no "opened" reply, unclear which errors end a session. Fixed at the protocol level: `serial-opened` is sent before any data (the machine opens the port, the WebSocket announces it, then reading starts), and only `serial-closed` ends an open session. Rules in docs/api.md.
- **The shell's list of server message types is keyed by the generated union**, so a new message type in the core is a TypeScript compile error until the shell handles it (it had silently dropped `serial-opened`).
- **Comments in parts.toml:** a comment block directly above a part goes with it on removal; anything above a blank line stays. New parts go after trailing comments (a comment-only file keeps its header on top).
- **Open:** capability `info` (e.g. LiDAR range min/max) has no place in the API yet, so the scan viewer fits the farthest point. Add `info` to `ProvideInfo`/`SignalInfo` when connector manifests carry it (Phase 3).
- **Open:** the LD19 connector doesn't judge rotation speed (the datasheet range wasn't verified), only silence and corrupted packets.
- The shell agent ran a broad `taskkill` on `node.exe` while testing; Mikkel's other node processes appeared to survive, but that's unverified.
